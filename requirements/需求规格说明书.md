## 1. 引言

### 1.1 编写目的

本文档是"在线考试系统"毕业设计项目的需求规格说明书（SRS），旨在对系统需要实现的功能与非功能需求进行完整、规范、可追溯的描述。本文档的主要读者与用途如下：

- **系统架构师**：依据本文档进行技术选型、架构设计与接口契约定义；
- **后端/前端开发人员**：依据本文档的功能需求编号（FR-XX-YY）进行模块开发与任务拆分；
- **测试人员**：依据本文档与用例图设计测试用例，进行功能与性能验证；
- **答辩评审教师**：依据本文档评估课题需求分析的完整性与合理性。

### 1.2 项目背景

随着教育信息化 2.0 行动计划的深入推进以及"互联网+教育"的普及，传统纸质考试在组织效率、阅卷周期、成绩统计、防作弊等方面已难以满足现代教学与培训的需求。尤其在高校课程考试、培训机构测评、企业招聘笔试等场景中，急需一个轻量级、易部署、流程完整的在线考试解决方案。

同类系统现状调研如下：

| 同类系统 | 优点 | 不足 |
|----------|------|------|
| 超星学习通考试模块 | 功能全面，支持大规模并发，移动端覆盖好 | 部署重，定制化差，小机构难以独立使用 |
| 智考网/考试酷 | 题库丰富，组卷灵活 | 广告多，数据归属不清晰，二次开发困难 |
| Moodle Quiz | 开源免费，插件生态好 | 中文体验差，组卷与统计偏弱，运维门槛高 |
| 校内自研系统 | 贴合本校流程 | 多为单点功能，缺乏全流程闭环，可维护性差 |

**研究意义**：本系统面向小规模（≤100 人并发）教育与培训场景，采用前后端分离架构（React + Node.js + MySQL），实现从题库建设、试卷组卷、在线考试、智能阅卷到成绩统计的全流程数字化闭环。系统具备轻量、易部署、可二次开发的特点，能够有效提升考试组织效率、缩短阅卷周期、支撑教学质量数据分析，同时为毕业设计提供一个完整全栈工程实践案例。

## 2. 总体描述

### 2.1 系统目标

构建一个支持管理员、教师、学生三类角色的在线考试系统，实现题库管理、试卷组卷、考试发布、在线答题、自动/人工阅卷、成绩统计的全流程闭环，满足 100 人以下并发考试需求，响应时间 < 2s，系统可用性 > 99%。

### 2.2 系统角色与特征

| 角色 | 标识 | 特征描述 | 核心职责 |
|------|------|----------|----------|
| 管理员 | Admin | 系统最高权限账户，通常由教务/IT 运维人员担任 | 系统用户管理、角色权限配置、系统参数配置、数据备份与日志查看 |
| 教师 | Teacher | 课程负责人或命题教师，具备教学与命题专业能力 | 题库管理（CRUD/批量导入导出）、试卷组卷、考试发布、阅卷（自动+手动）、成绩查看与统计 |
| 学生 | Student | 参加考试的受教育者，以学号标识 | 查看考试列表、在线答题（计时/防作弊/暂存）、提交试卷、查看成绩与答题详情 |

### 2.3 运行环境

| 项 | 说明 |
|----|------|
| 服务端 | Node.js 16+ / Express，MySQL 8.0 |
| 客户端 | 现代浏览器（Chrome、Firefox、Edge、Safari 最新两个大版本） |
| 部署 | 单机部署，前后端分离，前端静态资源由 Nginx 托管或后端托管 |
| 操作系统 | Windows / Linux 均可 |

### 2.4 系统边界

- **系统内**：用户认证、题库、试卷、考试、答题、阅卷、成绩统计等全部业务功能；
- **系统外**：不包含视频监考、人脸识别、直播教学、移动端原生 APP、多语言国际化、大规模高并发（>100 人）等。

## 3. 功能需求

> 编号规则：`FR-模块号-序号`，模块号采用两位数字。
> 模块号：01 用户管理 / 02 题库管理 / 03 试卷管理 / 04 考试管理 / 05 在线答题 / 06 阅卷 / 07 成绩统计。
> 优先级采用 MoSCoW 方法：Must（必须）/ Should（应该）/ Could（可以）/ Won't（暂不）。

| 编号 | 需求描述 | 输入 | 输出 | 优先级 |
|------|----------|------|------|--------|
| FR-01-01 | 用户登录：支持账号密码登录，登录成功后签发 JWT 令牌 | 账号、密码 | JWT 令牌、用户角色信息 | Must |
| FR-01-02 | 用户注册：管理员创建用户或开放学生自助注册（可配置） | 账号、姓名、角色、密码 | 创建结果 | Should |
| FR-01-03 | 角色权限控制：基于 RBAC 对管理员/教师/学生进行接口与页面级鉴权 | 用户角色、请求资源 | 允许/拒绝（403） | Must |
| FR-01-04 | 个人信息管理：用户查看与修改本人基本信息与头像 | 姓名、邮箱、头像等 | 更新结果 | Should |
| FR-01-05 | 修改密码：用户修改本人登录密码，密码加密存储 | 旧密码、新密码 | 修改结果 | Must |
| FR-01-06 | 用户管理（管理员）：管理员对用户进行 CRUD、重置密码、启用/禁用账号 | 用户信息、操作类型 | 操作结果 | Must |
| FR-01-07 | 班级/组织管理（管理员）：维护班级信息并将学生归属班级，便于考试指定 | 班级名称、学生列表 | 班级数据 | Should |

## 4. 非功能需求

> 编号规则：`NFR-序号`。

### 4.1 性能需求

| 编号 | 需求描述 | 量化指标 | 优先级 |
|------|----------|----------|--------|
| NFR-01 | 并发支持 | 支持 100 人同时在线考试，系统稳定无异常 | Must |
| NFR-02 | 响应时间 | 常规接口响应时间 < 2s，交卷接口 < 3s | Must |
| NFR-03 | 题库容量 | 单题库支持 ≥ 10000 道题目，查询响应 < 1s | Should |
| NFR-04 | 页面加载 | 首屏加载时间 < 3s（常规网络） | Should |

### 4.2 安全性需求

| 编号 | 需求描述 | 量化指标/实现方式 | 优先级 |
|------|----------|-------------------|--------|
| NFR-05 | 身份认证 | 采用 JWT 无状态认证，令牌有效期 2h，支持续期 | Must |
| NFR-06 | 权限控制 | 基于 RBAC 对接口与页面进行鉴权，越权返回 403 | Must |
| NFR-07 | SQL 注入防护 | 使用参数化查询/ORM，禁止拼接 SQL | Must |
| NFR-08 | XSS 防护 | 对用户输入进行转义，富文本采用白名单过滤 | Must |
| NFR-09 | 密码加密存储 | 密码使用 bcrypt 加盐哈希存储，禁止明文 | Must |
| NFR-10 | 敏感数据保护 | 考试答案、学生答卷等敏感数据接口需鉴权且最小暴露 | Must |

### 4.3 可用性需求

- 功能需求：`FR-模块号(2位)-序号(2位)`，如 `FR-02-06` 表示题库管理模块第 6 条需求。
