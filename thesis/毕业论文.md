# 在线考试系统的设计与实现

---

## 摘要

随着教育信息化的深入推进，传统纸质考试在组织效率、阅卷周期和成绩统计等方面已难以满足现代教学需求。本文设计并实现了一个面向小规模教育与培训场景的在线考试系统，旨在构建从题库建设、试卷组卷、在线考试、智能阅卷到成绩统计的全流程数字化闭环。

系统采用前后端分离的B/S架构，前端基于React 18框架，结合React Router 6路由管理、Zustand状态管理和Ant Design 5组件库构建单页应用；后端基于Node.js 18运行时和Express 4框架，采用路由层、控制器层、服务层、模型层四层分层架构；数据持久层采用MySQL 8.0关系型数据库与Sequelize 6 ORM框架；安全方面采用JWT无状态认证、RBAC角色权限控制、bcrypt密码加密等多重防护机制。系统支持管理员、教师、学生三类角色，实现了题库管理、手动与随机组卷、在线答题与防作弊、客观题自动阅卷与主观题手动阅卷、成绩分布统计与可视化等核心功能。

经测试验证，系统后端252个测试用例、前端33个测试用例全部通过，核心服务层覆盖率超过90%，满足100人并发考试的性能需求，系统功能完整、逻辑正确、异常处理规范，达到毕业设计交付标准。

**关键词**：在线考试；React；Node.js；MySQL；全栈开发

---

## Abstract

With the deepening of educational informatization, traditional paper-based examinations can no longer meet the needs of modern teaching in terms of organizational efficiency, grading cycle, and score statistics. This paper designs and implements an online examination system oriented toward small-scale education and training scenarios, aiming to build a full-process digital closed loop from question bank construction, paper assembly, online examination, intelligent grading, to score statistics.

The system adopts a front-end and back-end separated B/S architecture. The front-end is built with React 18 framework, combined with React Router 6 for routing, Zustand for state management, and Ant Design 5 component library to construct a single-page application. The back-end is based on Node.js 18 runtime and Express 4 framework, adopting a four-layer architecture of routes, controllers, services, and models. The data persistence layer uses MySQL 8.0 relational database and Sequelize 6 ORM framework. In terms of security, multiple protection mechanisms are adopted, including JWT stateless authentication, RBAC role-based access control, and bcrypt password encryption. The system supports three roles: administrator, teacher, and student, implementing core functions such as question bank management, manual and random paper assembly, online answering with anti-cheating, automatic grading for objective questions and manual grading for subjective questions, and score distribution statistics with visualization.

Through testing and verification, all 252 back-end test cases and 33 front-end test cases passed, with the core service layer coverage exceeding 90%. The system meets the performance requirement of 100 concurrent examinees, with complete functions, correct logic, and standardized exception handling, reaching the delivery standard of graduation design.

**Keywords**: Online Examination; React; Node.js; MySQL; Full-stack Development

## 第1章 绪论

### 1.1 研究背景与意义

考试作为教育教学过程中不可或缺的评价手段，其组织方式与执行效率直接影响教学质量反馈的及时性与准确性。长期以来，纸质考试在命题、印卷、分发、收卷、阅卷、登分、统计等环节耗费大量人力物力，且存在阅卷周期长、成绩统计易出错、防作弊手段有限等固有局限性。尤其在高校课程考试、培训机构测评、企业招聘笔试等高频场景中，传统考试模式已难以适应信息化时代对效率与精度的双重要求。

随着教育信息化2.0行动计划的深入推进以及"互联网+教育"理念的普及，在线考试系统应运而生并得到广泛应用。在线考试系统借助计算机网络技术，将命题、组卷、答题、阅卷、统计等全流程数字化，具有以下显著优势：其一，大幅缩短考试组织周期，教师可在线命题与组卷，学生可随时随地参加考试；其二，客观题自动阅卷机制将阅卷时间从天级压缩至秒级，显著提升反馈效率；其三，电子化答卷便于成绩的统计分析与数据挖掘，为教学质量改进提供数据支撑；其四，通过切屏检测、禁止复制粘贴等技术手段增强防作弊能力；其五，题库资源的积累与复用降低了命题成本。

然而，现有在线考试系统存在两极分化的问题：一方面，超星学习通、智考网等商业平台功能全面但部署重、定制化差、数据归属不清晰，小规模机构难以独立使用；另一方面，校内自研系统虽贴合本校流程，但多为单点功能，缺乏全流程闭环，可维护性较差。Moodle Quiz虽开源免费，但中文体验差、组卷与统计偏弱、运维门槛高。因此，面向小规模（100人以下并发）教育与培训场景，研发一个轻量级、易部署、流程完整、可二次开发的在线考试系统，具有重要的实践意义与应用价值。

本系统的研究意义体现在三个层面：在应用层面，为小规模教育与培训机构提供一套从题库建设到成绩统计的全流程数字化解决方案，有效提升考试组织效率、缩短阅卷周期、支撑教学质量数据分析；在技术层面，验证React+Node.js+MySQL全栈技术栈在中后台管理系统中的工程适用性，探索前后端分离架构下的分层设计、安全认证与防作弊机制实现；在教育层面，为毕业设计提供一个完整的全栈工程实践案例，涵盖需求分析、系统设计、编码实现、测试验证的完整软件生命周期。

具体而言，本系统的研究意义可归纳为以下几点：第一，通过在线答题与客观题自动阅卷，将传统考试中耗时最长的答题与阅卷环节从小时级压缩至分钟级，显著提升考试反馈效率；第二，通过题库资源的积累与复用，降低命题成本，支持知识点与难度维度的题目分类管理，为科学组卷提供数据基础；第三，通过成绩分布统计与分析指标计算，为教师提供量化的教学质量评估依据，支撑教学改进决策；第四，通过切屏检测、禁止复制粘贴等前端防作弊机制，在一定程度上保障考试公平性；第五，系统采用开源技术栈与前后端分离架构，代码结构清晰、模块解耦，可作为同类系统的参考实现与二次开发基础。

### 1.2 国内外研究现状

**国外研究现状**：在线考试系统的研究起步较早。Moodle作为全球应用最广泛的开源学习管理系统，其Quiz模块支持多种题型与随机组卷，但中文本地化体验欠佳，组卷与统计功能相对薄弱。ExamSoft、ProctorU等商业平台集成了在线监考与人脸识别功能，适用于高利害考试场景，但部署成本与使用门槛较高。Canvas、Blackboard等LMS平台内置考试模块，与课程管理深度集成，但独立部署能力有限。在技术研究层面，国外学者在自动阅卷算法、防作弊机制、自适应测试等方面积累了丰富成果，如基于自然语言处理的主观题自动评分、基于浏览器行为的异常检测等。

**国内研究现状**：国内在线考试系统的发展与教育信息化进程紧密相关。超星学习通考试模块功能全面，支持大规模并发与移动端覆盖，但部署重、定制化差。智考网、考试酷等在线平台题库丰富、组卷灵活，但存在广告多、数据归属不清晰、二次开发困难等问题。各大高校普遍采用校内自研或采购定制的方式建设考试系统，如基于Java Web的考试系统、基于PHP的在线测试平台等，但多数系统技术栈陈旧、架构单一、可维护性不足。近年来，随着前后端分离架构与JavaScript全栈技术的成熟，基于React/Vue+Node.js的现代化考试系统逐渐成为研究与开发热点。

**发展趋势**：在线考试系统正朝着智能化、移动化、数据化方向发展。智能化体现在主观题自动阅卷、自适应出题、学习路径推荐等AI赋能场景；移动化体现在响应式Web与原生APP的多端覆盖；数据化体现在考试数据的深度分析与可视化呈现。本系统聚焦于全流程闭环与工程化实现，在保证核心功能完整的前提下，为后续智能化扩展预留接口。

**对比分析与本系统定位**：综合调研可知，现有系统要么功能全面但部署重、定制化差、数据归属不清晰（如超星学习通、ExamSoft），要么轻量但功能单薄、缺乏全流程闭环（如校内自研系统）。本系统定位于小规模（100人以下并发）教育与培训场景，在功能完整性与轻量易部署之间取得平衡：一方面实现从题库建设、试卷组卷、在线考试、智能阅卷到成绩统计的全流程闭环，覆盖管理员、教师、学生三类角色的完整业务场景；另一方面采用前后端分离的现代化技术栈，单机部署即可运行，代码结构清晰、模块解耦，便于二次开发与功能扩展。相较于Moodle Quiz的中文体验欠佳与运维门槛高，本系统全中文界面、统一错误提示、开箱即用的Ant Design组件，显著降低了使用与维护成本。

本系统的研究内容主要包括以下几个方面：

## 第2章 相关技术介绍

### 2.1 前端技术

**React 18**：React是由Facebook开源的声明式、组件化JavaScript UI库，用于构建用户界面。React 18引入了并发渲染特性，支持自动批处理、过渡更新等新能力。其核心思想包括组件化开发（将UI拆分为独立可复用的组件，通过组合构建复杂界面）、虚拟DOM（通过内存中的虚拟节点树与真实DOM进行diff比对，最小化DOM操作以提升渲染性能）以及Hooks机制（useEffect、useState、useRef、useCallback等函数式API，使函数组件具备状态与副作用管理能力，替代了类组件的this与生命周期心智负担）。本系统采用React 18构建单页应用（SPA），通过组件化组织登录、用户管理、题库、试卷、考试、答题、阅卷、成绩等页面，利用Hooks管理组件内状态与副作用，通过React.lazy与Suspense实现路由级代码分割与懒加载，优化首屏加载性能。

**React Router 6**：React Router是React生态中事实标准的路由管理库，本系统采用v6版本。其支持嵌套路由配置、动态路由参数、懒加载（通过React.lazy与Suspense实现代码分割）以及路由守卫。本系统通过React Router 6实现管理员、教师、学生三端的页面路由与权限控制，结合ProtectedRoute组件实现基于角色的路由级鉴权。

**Zustand状态管理**：Zustand是一个轻量级的状态管理库，相较于Redux具有无样板代码、API简洁、TypeScript友好的优势。本系统采用Zustand管理全局认证状态（authStore，存储JWT令牌与用户信息）与考试状态（examStore，管理试卷题目、答案暂存、倒计时、切屏计数等），通过create函数创建store，组件通过hook直接订阅与更新状态。Zustand的store定义采用闭包模式，set函数用于更新状态，get函数用于读取当前状态，支持在store外部通过useExamStore.getState()获取最新状态，便于在定时器与事件监听器等非组件上下文中访问与更新状态，这一特性在考试倒计时与答案暂存定时同步场景中尤为重要。

**Ant Design 5**：Ant Design是面向企业级中后台产品的React组件库，提供表格、表单、上传、图表、模态框等丰富组件。本系统采用Ant Design 5构建管理后台界面，利用其Table组件展示题库与成绩列表、Form组件实现题目编辑与考试配置、Upload组件实现Excel批量导入、Modal组件实现交卷确认与切屏警告，大幅提升开发效率。

**Vite构建工具**：Vite是基于ESM的下一代前端构建工具，提供极速冷启动与HMR（热模块替换）能力。相较于Webpack，Vite在开发阶段利用浏览器原生ESM按需编译，启动时间从秒级降至毫秒级；生产构建采用Rollup，产物体积小、Tree-shaking效果好。本系统采用Vite 5作为前端构建工具。

**Axios**：Axios是基于Promise的HTTP客户端，支持请求与响应拦截器、超时控制、自动JSON转换等特性。本系统通过Axios封装统一的请求实例，在请求拦截器中自动注入JWT令牌（Authorization: Bearer），在响应拦截器中统一处理业务错误码与401跳转登录，实现前后端通信的统一管理。响应拦截器对统一响应格式{code, message, data}进行解析，code为200时返回完整响应供业务使用，非200时通过Ant Design message组件弹出错误提示并reject Promise；对HTTP层错误（401未认证、403无权限、404不存在、409冲突等）进行状态码分发处理，401时自动清除本地令牌并跳转登录页，避免在登录页循环跳转。

### 2.2 后端技术

**Node.js 18**：Node.js是基于V8引擎的JavaScript运行时，采用事件驱动、非阻塞I/O模型，适合高并发I/O密集型场景。本系统采用Node.js 18 LTS作为后端运行时，其非阻塞特性契合考试并发答题与答案暂存场景，前后端同语言（JavaScript）降低了全栈开发的心智成本与上下文切换开销。

**Express 4框架**：Express是Node.js最流行的Web应用框架，以轻量、灵活、中间件生态丰富著称。本系统采用Express 4构建RESTful API服务，通过中间件链组织CORS跨域、日志记录、JWT认证、RBAC权限校验、参数校验、错误处理等横切关注点，业务逻辑按模块划分至独立的控制器与服务层。

**Sequelize 6 ORM**：Sequelize是面向Node.js的Promise-based ORM框架，支持MySQL、PostgreSQL等多种数据库，提供模型定义、关联映射、事务管理、查询构建器、参数化查询等能力。本系统采用Sequelize 6定义10个数据模型，通过模型关联表达实体间的一对多与多对多关系，利用参数化查询从机制上防御SQL注入，通过事务保证组卷、交卷、阅卷等复合操作的原子性。Sequelize的Scope机制用于控制字段暴露范围，本系统在User模型中定义defaultScope排除password_hash字段、withPassword scope在登录校验时显式引入，从模型层保障敏感数据最小暴露。此外，Sequelize的软删除模式（paranoid）通过deleted_at字段实现逻辑删除，避免物理删除导致外键引用断裂，本系统在questions、papers、exams等核心业务表应用此模式。

**JWT认证**：JSON Web Token（JWT）是一种无状态的认证令牌标准，由Header、Payload、Signature三部分组成。本系统采用jsonwebtoken库签发与校验JWT，Payload中携带userId与role信息，有效期设为2小时。JWT的无状态特性契合前后端分离架构，服务端无需维护会话，令牌自包含身份信息，便于水平扩展。

**bcrypt密码加密**：bcrypt是面向密码哈希的加密算法，内置加盐机制，抗彩虹表攻击。本系统采用bcryptjs库，saltRounds设为10，注册与重置密码时通过bcrypt.hash存储哈希值，登录时通过bcrypt.compare校验，确保密码不以明文形式存储于数据库。

### 2.3 数据库技术

**MySQL 8.0**：MySQL是全球应用最广泛的开源关系型数据库管理系统，支持事务、索引、视图、存储过程等特性。本系统采用MySQL 8.0存储业务数据，字符集设为utf8mb4以支持中文与Emoji字符，存储引擎采用InnoDB以支持事务与行级锁。数据库设计遵循规范化原则，通过外键约束保证引用完整性，通过联合索引优化题库筛选与阅卷任务查询等高频查询路径。

**数据库设计原则**：本系统数据库设计遵循以下原则：其一，规范化与反规范化结合，核心业务表满足第三范式以消除数据冗余，对高频查询场景适当冗余以减少关联查询；其二，主键统一采用BIGINT自增，保证唯一性与有序性；其三，核心业务表（questions、papers、exams）采用软删除（deleted_at字段），避免物理删除导致引用断裂；其四，敏感字段（password_hash）通过模型defaultScope默认排除，防止意外泄露。

### 2.4 其他技术

**RESTful API设计规范**：REST（Representational State Transfer）是一种基于HTTP的Web服务架构风格，强调资源化URL设计、HTTP动词语义化、无状态通信。本系统遵循RESTful规范设计接口，以名词复数标识资源集合（如/api/users、/api/questions），通过GET、POST、PUT、PATCH、DELETE动词表达查询、新增、更新、删除语义，对动作型接口（如发布考试、交卷）采用POST+动词后缀的形式。所有接口统一返回{code, message, data}结构，便于前端统一处理。

**B/S架构与前后端分离**：本系统采用B/S（Browser/Server）架构，用户通过浏览器访问系统，无需安装客户端。在此基础上进一步采用前后端分离架构，前端React SPA独立构建与部署，后端Express提供纯API服务，两者通过HTTPS+JSON通信。前后端分离使前后端可独立开发、独立部署、独立演进，通过OpenAPI接口契约实现解耦协作。

### 3.3 功能需求分析

**（1）用户管理模块（FR-01，9条需求）**：涵盖用户登录（JWT签发）、用户注册、RBAC角色权限控制、个人信息管理、修改密码、管理员用户CRUD、班级组织管理、系统配置、数据备份与日志。其中登录、权限控制、修改密码、用户管理为Must级需求，构成系统安全与用户管理的基础。

**（2）题库管理模块（FR-02，9条需求）**：涵盖题目新增（支持单选、多选、判断、填空、简答5种题型）、题目编辑、题目删除（引用校验）、题目查询（按题型/知识点/难度/关键字筛选分页）、题目详情、Excel批量导入、Excel批量导出、知识点与难度分类管理、题目预览。题库管理是教师命题工作的核心，5种题型的统一管理为组卷提供基础。

**（3）试卷管理模块（FR-03，8条需求）**：涵盖手动组卷（教师从题库选题，调整顺序与分值）、随机组卷（按规则自动抽题）、试卷设置（总分/时长/及格线/乱序）、试卷预览、试卷编辑、试卷删除（引用校验）、试卷列表查询、试卷复制。手动组卷与随机组卷两种模式满足不同命题场景需求。

**（4）考试管理模块（FR-04，8条需求）**：涵盖发布考试（基于试卷创建考试）、考试时间设置、指定参考班级/学生、考试状态管理（草稿/已发布/进行中/已结束状态流转）、考试列表查询、考试编辑、考试删除/停用、考试详情查看。考试管理将试卷与参考人员关联，控制考试的时间窗口与生命周期。

**（5）在线答题模块（FR-05，9条需求）**：涵盖学生查看考试列表、进入考试（身份与时间校验）、题目导航（答题卡）、答案暂存（断网续答）、计时提醒（剩余5分钟弹窗）、防作弊切屏检测、防作弊禁止复制粘贴、交卷（主动/自动）、答题详情查看。在线答题是学生侧的核心功能，防作弊机制是重点与难点。

**（6）阅卷模块（FR-06，5条需求）**：涵盖客观题自动阅卷（单选/多选/判断/填空自动评分）、主观题手动阅卷（简答逐题评分与评语）、阅卷任务列表、成绩复核（改分留痕）、阅卷进度查看。自动阅卷大幅提升客观题评分效率，手动阅卷保证主观题评分的灵活性。

**（7）成绩统计模块（FR-07，6条需求）**：涵盖学生个人成绩查询、教师班级成绩查看、成绩分布统计（分数段人数与图表）、成绩分析指标（最高/最低/平均/及格率/标准差）、成绩单Excel导出、学生错题统计。成绩统计为教学质量分析提供数据支撑。

综上，本系统共定义54条功能需求，其中Must级32条构成MVP（最小可行产品）范围，Should级17条为重要但非阻塞项，Could级5条为锦上添花功能。需求优先级采用MoSCoW方法标注，为迭代开发与范围管理提供依据。各模块需求之间存在依赖关系：题库管理是试卷管理的前提，试卷管理是考试管理的前提，考试管理是在线答题的前提，在线答题是阅卷的前提，阅卷是成绩统计的前提，形成从题库到成绩的线性依赖链。

### 3.4 非功能需求分析

本系统定义22条非功能需求，涵盖以下维度：

**性能需求**：支持100人同时在线考试（NFR-01）；常规接口响应时间小于2秒，交卷接口小于3秒（NFR-02）；单题库支持10000道以上题目，查询响应小于1秒（NFR-03）；首屏加载时间小于3秒（NFR-04）。

**兼容性需求**：兼容Chrome、Firefox、Edge、Safari最新两个大版本（NFR-19）；适配PC与平板分辨率（NFR-20）。

**可扩展性需求**：题型采用配置化设计便于扩展（NFR-21）；模块化解耦便于接入缓存与通知（NFR-22）。

非功能需求为系统质量属性提供了量化约束与实现指引，与功能需求共同构成完整的需求规格。其中性能与安全性需求为Must级，是系统交付的硬性指标；可用性与可维护性需求兼顾用户体验与工程质量；兼容性与可扩展性需求面向系统的长期演进。在设计与实现阶段，各项非功能需求均有对应的技术措施落地：性能需求通过连接池、索引优化与前端代码分割保障；安全性需求通过JWT、RBAC、bcrypt、ORM参数化查询与输入转义多重防护；可用性需求通过统一错误处理、断网续答与自动交卷保障；可维护性需求通过分层架构、代码规范与接口文档保障。

### 4.4 模块设计

本系统按业务域划分为7个模块，各模块设计如下：

**用户管理模块**：路由前缀/api/auth、/api/users、/api/classes，核心API包括登录、注册、个人信息、修改密码、用户CRUD、班级CRUD。关键逻辑为bcrypt加盐哈希存储密码、JWT签发含userId与role、RBAC中间件按角色校验。

**题库管理模块**：路由前缀/api/questions，支持5种题型(single/multiple/judge/fill/short)，options字段存JSON，删除时校验是否被试卷引用，批量导入导出通过exceljs解析与生成Excel。

**试卷管理模块**：路由前缀/api/papers，手动组卷维护paper_questions关联，随机组卷按题型/知识点/难度/数量从题库随机抽取，总分自动汇总，删除校验是否被考试引用。

**考试管理模块**：路由前缀/api/exams，状态机draft→published→ongoing→finished，发布时校验时间窗口，进行中不允许删除，通过exam_classes关联指定参考班级。考试状态流转遵循严格规则：草稿状态可编辑与发布，发布后进入已发布状态等待时间窗口到达，到达开始时间自动流转为进行中，到达结束时间流转为已结束。进行中与已结束状态的考试禁止删除，保证考试数据的完整性。

**在线答题模块**：进入考试校验时间窗口与身份，创建/复用exam_records；暂存upsert到answers表；交卷触发客观题自动阅卷；防作弊在前端监听切屏与复制并记录。进入考试时进行多重校验：考试状态必须为已发布或进行中、当前时间必须处于考试时间窗口内、学生必须属于指定参考班级、学生未已交卷（防止重复进入），任一校验失败返回对应的业务错误码与提示信息。

**阅卷模块**：客观题自动阅卷比对student_answer与标准answer（单选/判断完全匹配，多选集合相等，填空去空格匹配）；主观题由教师逐题评分并记录graded_by/graded_at；复核保留修改记录。

**成绩统计模块**：统计最高/最低/平均/及格率/标准差；按分数段(0-59/60-69/70-79/80-89/90-100)统计人数；导出用exceljs生成xlsx。

各模块间通过Service层函数调用通信，共享同一MySQL连接池。模块间存在明确的依赖关系：题库管理为试卷管理提供题目数据源，试卷管理为考试管理提供试卷基础，考试管理为在线答题提供考试实例与时间窗口控制，在线答题为阅卷模块提供答卷数据，阅卷模块为成绩统计提供评分结果。这种线性依赖链保证了数据流向的清晰性，同时通过模块化设计实现功能解耦，便于独立开发、测试与维护。

### 4.5 安全设计

**JWT认证流程**：用户提交账号密码至POST /api/auth/login，后端查询users表并通过bcrypt.compare校验密码哈希，校验通过后签发JWT（Payload含userId、role、iat、exp，有效期2小时），前端将JWT存于localStorage，Axios请求拦截器自动注入Authorization: Bearer头，后端认证中间件解析并校验JWT，失败返回401。

**RBAC权限模型**：系统定义admin、teacher、student三种角色，路由声明所需角色，权限中间件从JWT解析role并校验，不匹配返回403。提供requireAdmin、requireTeacher、requireStudent及requireAdminOrTeacher等快捷方法支持单角色与多角色校验。

**SQL注入防护**：全部数据库操作通过Sequelize ORM参数化查询，禁止SQL字符串拼接，从机制上防御SQL注入攻击。原生查询使用replacements参数绑定。

**XSS防护**：后端对用户输入进行HTML转义后存储，前端React默认转义JSX插值，富文本内容采用白名单过滤，设置X-Content-Type-Options: nosniff响应头。

**密码加密**：采用bcrypt算法，saltRounds=10，注册与重置时bcrypt.hash存储哈希，登录时bcrypt.compare校验，禁止任何日志或响应输出密码明文或哈希。

**其他防护**：登录接口限流（express-rate-limit，5次/分钟）防御暴力破解；敏感数据接口严格鉴权，学生阅卷完成前不可获取标准答案；生产环境强制HTTPS；CORS仅允许前端部署域名。

### 5.2 用户认证与权限模块实现

用户认证模块由authService.js实现登录、注册、个人信息与密码修改逻辑。登录核心实现如下：

```javascript
// 登录服务（backend/src/services/authService.js）
async function login({ username, password }) {
  // 查询用户（含密码哈希）
  const user = await User.scope('withPassword').findOne({ where: { username } });
  if (!user) {
    throw new BizError(config.codes.USERNAME_OR_PASSWORD_ERROR, '用户名或密码错误');
  }
  // 校验密码
  const matched = await bcrypt.compare(password, user.password_hash);
  if (!matched) {
    throw new BizError(config.codes.USERNAME_OR_PASSWORD_ERROR, '用户名或密码错误');
  }
  // 校验账号状态
  if (user.status !== 'active') {
    throw new BizError(config.codes.ACCOUNT_DISABLED, '账号已禁用，请联系管理员');
  }
  // 签发 JWT
  const token = jwt.sign(
    { userId: user.id, role: user.role },
    config.jwt.secret,
    { expiresIn: config.jwt.expiresIn }
  );
  return { token, userInfo: toUserInfo(user) };
}
```

该实现依次完成用户查询、密码校验、状态校验与令牌签发四步，任何一步失败均抛出BizError业务异常，由全局错误处理中间件统一捕获并返回结构化错误响应。toUserInfo函数将用户对象转换为DTO，剔除password_hash字段，防止敏感数据泄露（满足NFR-10）。

JWT认证中间件实现如下：

```javascript
// 认证中间件（backend/src/middlewares/auth.js）
function auth(required = true) {
  return (req, res, next) => {
    const authHeader = req.headers.authorization || '';
    const token = authHeader.startsWith('Bearer ') ? authHeader.slice(7) : null;
    if (!token) {
      if (!required) return next();
      return fail(res, config.codes.UNAUTHORIZED, '未认证或令牌缺失', null, 401);
    }
    try {
      const payload = jwt.verify(token, config.jwt.secret);
      req.user = { userId: payload.userId, role: payload.role };
      next();
    } catch (err) {
      if (err.name === 'TokenExpiredError') {
        return fail(res, config.codes.UNAUTHORIZED, '令牌已过期，请重新登录', null, 401);
      }
      return fail(res, config.codes.UNAUTHORIZED, '令牌无效', null, 401);
    }
  };
}
```

RBAC权限中间件实现如下：

```javascript
// 权限中间件（backend/src/middlewares/rbac.js）
function requireRole(...roles) {
  return (req, res, next) => {
    if (!req.user || !req.user.role) {
      return fail(res, config.codes.UNAUTHORIZED, '未认证', null, 401);
    }
    if (!roles.includes(req.user.role)) {
      return fail(res, config.codes.FORBIDDEN, '无权限访问该资源', null, 403);
    }
    next();
  };
}
```

路由层通过组合auth与requireRole中间件实现接口级鉴权，例如router.post('/api/users', auth(), requireRole('admin'), userController.create)限定仅管理员可创建用户。

### 5.3 题库管理模块实现

题库管理模块由questionService.js实现题目CRUD、分页查询与批量导入导出。题目查询支持按题型、难度、知识点、关键字多维筛选与分页，核心查询逻辑如下：

```javascript
// 题目分页查询（backend/src/services/questionService.js）
async function listQuestions({ page, pageSize, offset, limit, type, difficulty, knowledge_point, keyword }) {
  const where = { deleted_at: null };
  if (type) where.type = type;
  if (difficulty) where.difficulty = parseInt(difficulty, 10);
  if (knowledge_point) where.knowledge_point = { [Op.like]: `%${knowledge_point}%` };
  if (keyword) {
    where[Op.or] = [
      { content: { [Op.like]: `%${keyword}%` } },
      { knowledge_point: { [Op.like]: `%${keyword}%` } },
    ];
  }
  const { rows, count } = await Question.findAndCountAll({
    where, offset, limit,
    order: [['id', 'DESC']],
    include: [{ model: User, as: 'creator', attributes: ['id', 'real_name'] }],
  });
  return { list: rows.map(toQuestionInfo), total: count, page, pageSize };
}
```

题目删除时校验是否被试卷引用，若被引用则抛出业务错误禁止删除（错误码2001），保证数据引用完整性。批量导入通过exceljs解析Excel文件，逐行校验格式后批量写入题库，返回成功与失败条数及错误明细；批量导出按筛选条件查询题目并通过exceljs生成Excel文件下载。

### 5.4 试卷管理与组卷实现

试卷管理模块由paperService.js实现试卷CRUD、手动组卷、随机组卷与预览。随机组卷是本模块的核心算法，按教师设定的组卷规则（题型分布、知识点、难度、各题型数量与分值）从题库随机抽取题目，实现如下：

```javascript
// 随机组卷（backend/src/services/paperService.js）
async function autoGenerate(creatorId, { name, duration, pass_score, is_random_order, rules, description }) {
  const t = await sequelize.transaction();
  try {
    let totalScore = 0;
    const allPQ = [];
    let sortOrder = 0;
    for (const rule of rules) {
      const where = { deleted_at: null, type: rule.type };
      if (rule.difficulty) where.difficulty = rule.difficulty;
      if (rule.knowledge_point) where.knowledge_point = { [Op.like]: `%${rule.knowledge_point}%` };
      const candidates = await Question.findAll({ where, attributes: ['id'], transaction: t });
      if (candidates.length < rule.count) {
        throw new BizError(config.codes.BAD_REQUEST,
          `题型${rule.type}满足条件的题目不足，需要${rule.count}题，实际仅${candidates.length}题`);
      }
      // 随机抽取
      const shuffled = candidates.sort(() => Math.random() - 0.5);
      const picked = shuffled.slice(0, rule.count);
      for (const q of picked) {
        allPQ.push({ question_id: q.id, score: rule.score, sort_order: sortOrder++ });
        totalScore += parseFloat(rule.score);
      }
    }
    const paper = await Paper.create({ name, total_score: totalScore, duration, pass_score,
      is_random_order: is_random_order ? 1 : 0, creator_id: creatorId, status: 'draft' }, { transaction: t });
    for (const pq of allPQ) {
      await PaperQuestion.create({ paper_id: paper.id, ...pq }, { transaction: t });
    }
    await t.commit();
    return toPaperInfo(paper, allPQ.length);
  } catch (e) {
    await t.rollback();
    throw e;
  }
}
```

该算法遍历每条组卷规则，按题型、难度、知识点筛选候选题目，校验题库是否充足，通过Math.random()随机排序后截取所需数量，累加总分并写入paper_questions关联。整个过程在数据库事务中执行，任一规则失败则回滚，保证组卷的原子性。手动组卷则由addQuestions函数实现，教师逐题选择并设定分值与排序，通过upsert语义支持已存在题目的分值更新。

试卷删除采用软删除策略，deletePaper函数首先校验试卷是否被考试引用（查询exams表中paper_id匹配且未软删除的记录），若存在引用则抛出业务错误（错误码3001）禁止删除，避免删除被引用试卷导致考试数据断裂；若无引用则在事务中先删除paper_questions关联记录，再将试卷的deleted_at置为当前时间实现软删除。试卷预览功能通过getPaper函数查询试卷详情，按sort_order排序返回题目列表及分值，供教师组卷时实时预览试卷结构与题目渲染效果。

```javascript
},
```

前端通过定时器每30秒将暂存答案批量同步至服务端saveAnswer接口，作答时通过节流函数（2秒间隔）即时同步，网络失败时静默重试，保证答案不丢失。

**防作弊机制**：ExamPage通过监听document的visibilitychange事件实现切屏检测，记录切屏次数，超过阈值（MAX_SWITCH_COUNT）时弹窗警告并自动交卷；通过拦截copy、paste、cut、contextmenu事件禁止复制粘贴与右键菜单；通过beforeunload事件在离开页面前提示。核心实现如下：

```javascript
// 防作弊：切屏检测（frontend/src/pages/student/ExamPage.jsx）
const handleVisibilityChange = () => {
  if (document.hidden) {
```

### 5.6 阅卷模块实现

阅卷模块由gradeService.js实现客观题自动阅卷、主观题手动阅卷、阅卷任务管理与进度统计。客观题自动阅卷在交卷时触发，核心算法如下：

```javascript
// 自动阅卷（backend/src/services/gradeService.js）
async function autoGradeRecord(recordId) {
  const record = await ExamRecord.findByPk(recordId);
  const exam = await Exam.findByPk(record.exam_id);
  const pqs = await PaperQuestion.findAll({
    where: { paper_id: exam.paper_id },
    include: [{ model: Question, as: 'question' }],
  });
  const pqMap = new Map(pqs.map(pq => [pq.question_id, pq]));
  const answers = await Answer.findAll({ where: { exam_record_id: recordId } });
  let objectiveScore = 0;
  let hasSubjective = false;
  const t = await sequelize.transaction();
  try {
    for (const ans of answers) {
      const pq = pqMap.get(ans.question_id);
      const question = pq.question;
      const fullScore = parseFloat(pq.score);
      if (OBJECTIVE_TYPES.includes(question.type)) {
        const isCorrect = compareAnswer(question.type, ans.student_answer, question.answer);
        const score = isCorrect ? fullScore : 0;
        await ans.update({ score, is_correct: isCorrect ? 1 : 0,
          graded_by: null, graded_at: new Date() }, { transaction: t });
        objectiveScore += score;
      } else if (SUBJECTIVE_TYPES.includes(question.type)) {
        hasSubjective = true;
      }
    }
    if (!hasSubjective) {
      await record.update({ total_score: objectiveScore, status: 'graded' }, { transaction: t });
    } else {
      // 生成阅卷任务待教师处理
      // ...
    }
    await t.commit();
  } catch (e) { await t.rollback(); throw e; }
  return { objective_score: objectiveScore, has_subjective: hasSubjective };
}
```

答案比对函数compareAnswer根据题型采用不同策略：单选与判断题完全匹配；多选题通过集合相等比较（忽略选项顺序）；填空题支持多空匹配（以||分隔，去空格）。若试卷包含主观题（简答题），则生成阅卷任务（grade_tasks）待教师手动评分；若无主观题，直接汇总成绩并将考试记录状态置为graded。

客观题与主观题的区分通过题型常量实现：OBJECTIVE_TYPES包含single、multiple、judge、fill四种题型，由系统自动阅卷；SUBJECTIVE_TYPES包含short简答题，需教师手动阅卷。自动阅卷在数据库事务中逐条更新answers表的score、is_correct、graded_by（NULL表示系统）、graded_at字段，任一题目评分失败则事务回滚，保证阅卷结果的原子性与一致性。当检测到主观题时，通过GradeTask模型创建阅卷任务记录，统计该考试已交卷答卷总数作为total_count，graded_count初始为0，状态为pending，等待教师进入阅卷中心逐题评分。

主观题手动阅卷由gradeAnswers函数实现，教师逐题填写评分与评语，系统更新answers表的score、is_correct、comment、graded_by、graded_at字段，并在所有题目评分完成后汇总总成绩、更新阅卷任务进度。成绩复核支持对已阅卷答卷改分，保留graded_by与graded_at修改记录。

### 5.7 成绩统计模块实现

成绩统计模块由scoreService.js实现个人成绩查询、班级成绩查看、分布统计、导出与错题统计。分布统计与分析指标计算核心实现如下：

```javascript
// 成绩分布统计（backend/src/services/scoreService.js）
async function getStatistics(examId) {
  const records = await ExamRecord.findAll({
    where: { exam_id: examId, status: 'graded' }, attributes: ['total_score'],
  });
  const scores = records.map(r => parseFloat(r.total_score || 0));
  const maxScore = Math.max(...scores);
  const minScore = Math.min(...scores);
  const avgScore = scores.reduce((a, b) => a + b, 0) / scores.length;
  const passCount = scores.filter(s => s >= passScore).length;
  const passRate = Math.round((passCount / scores.length) * 10000) / 100;
  // 标准差
  const variance = scores.reduce((acc, s) => acc + Math.pow(s - avgScore, 2), 0) / scores.length;
  const stdDeviation = Math.sqrt(variance);
  // 分数段分布
  const distribution = [
    { range: '0-59', count: 0 }, { range: '60-69', count: 0 },
    { range: '70-79', count: 0 }, { range: '80-89', count: 0 },
    { range: '90-100', count: 0 },
  ];
  for (const s of scores) {
    if (s < 60) distribution[0].count++;
    else if (s < 70) distribution[1].count++;
    else if (s < 80) distribution[2].count++;
    else if (s < 90) distribution[3].count++;
    else distribution[4].count++;
  }
  return { max_score: maxScore, min_score: minScore, avg_score: avgScore,
    pass_rate: passRate, std_deviation: stdDeviation, distribution };
}
```

该函数计算最高分、最低分、平均分、及格率与标准差五项分析指标，并按0-59、60-69、70-79、80-89、90-100五个分数段统计人数分布，为教学质量分析提供量化依据。其中标准差通过方差开方计算，反映成绩的离散程度，标准差越小表明成绩越集中、教学效果越均衡；及格率以试卷设定的及格线为阈值统计达标比例。当无已阅卷记录时返回零值默认结构，避免空数据导致的计算异常。

前端成绩统计页面（ScoreStatistics.jsx）基于ECharts可视化库渲染成绩分布柱状图与饼图，结合Ant Design的Statistic组件展示分析指标卡片、Table组件展示班级成绩明细表，支持按考试与班级筛选及成绩单Excel导出。错题统计功能为学生汇总各考试的错题及参考答案与解析，便于针对性复习。

成绩单导出功能通过exportScores函数实现，查询指定考试与班级的学生及其考试记录，通过buildScoreExcel工具函数（基于exceljs）生成包含学号、姓名、班级、成绩、是否及格、交卷时间等列的Excel文件，以Buffer形式返回前端，前端通过Blob对象触发浏览器下载。错题统计通过getWrongQuestions函数查询学生各考试中is_correct为0的答题记录，关联题目表获取题干、参考答案与解析，为学生提供错题复习的数据支撑。
