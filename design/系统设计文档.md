| 方案 | 优点 | 不足 | 结论 |

## 2. 系统总体架构

### 2.1 架构风格

- **B/S 架构**：用户通过浏览器访问，无需安装客户端。
- **前后端分离**：前端 React SPA 独立构建，后端 Express 提供 RESTful API，通过 Axios 通信。
- **RESTful API**：资源化 URL 设计，HTTP 动词语义化，统一 JSON 响应。
- **分层架构**：后端采用 `routes → controllers → services → models` 四层，职责清晰（满足 NFR-18）。

### 2.3 服务职责与通信方式

本系统为**单体应用**（毕设规模，≤100 并发，不做微服务拆分），内部按业务域划分**模块**，模块间通过 Service 层函数调用通信，共享同一 MySQL 实例与连接池。

| 模块 | 职责 | 对应需求 |
|------|------|----------|
| 用户管理模块 | 登录/注册/鉴权/用户CRUD/班级管理/系统配置 | FR-01-01~09 |
| 题库管理模块 | 题目CRUD/批量导入导出/知识点分类 | FR-02-01~09 |
| 试卷管理模块 | 手动/随机组卷/试卷配置/预览/复制 | FR-03-01~08 |
| 考试管理模块 | 考试发布/时间/班级/状态管理 | FR-04-01~08 |
| 在线答题模块 | 考试列表/进入考试/答题暂存/计时/防作弊/交卷 | FR-05-01~09 |
| 阅卷模块 | 客观题自动阅卷/主观题手动阅卷/阅卷任务/复核 | FR-06-01~05 |
| 成绩统计模块 | 个人/班级成绩/分布统计/分析指标/导出/错题 | FR-07-01~06 |

### 2.4 数据流

1. **答题数据流**：学生作答 → 前端暂存(localStorage) → 定时 POST 暂存接口 → `answers` 表 → 交卷 → 触发客观题自动阅卷 → 更新 `exam_records` 与 `answers` 得分。
2. **阅卷数据流**：交卷 → 客观题自动评分 → 生成主观题阅卷任务(`grade_tasks`) → 教师手动评分 → 汇总成绩 → 成绩统计。
3. **组卷数据流**：教师选题 → `paper_questions` 关联 → 发布考试 → 指定班级(`exam_classes`) → 学生进入考试拉取试卷快照。

## 4. 数据库设计

### 4.1 分库策略

本系统为单体应用，采用**单库多表**策略，库名 `online_exam`，字符集 `utf8mb4`，排序规则 `utf8mb4_general_ci`。不进行分库分表（数据量级 ≤ 10 万题、≤ 1 万考生，单库足够）。

### 4.2 表清单

| 表名 | 说明 | 关联需求 |
|------|------|----------|
| `users` | 用户表（管理员/教师/学生） | FR-01 |
| `classes` | 班级表 | FR-01-07 |
| `questions` | 题目表（5 种题型） | FR-02 |
| `papers` | 试卷表 | FR-03 |
| `paper_questions` | 试卷-题目关联表 | FR-03-01 |
| `exams` | 考试表 | FR-04 |
| `exam_classes` | 考试-班级关联表 | FR-04-03 |
| `exam_records` | 考试记录表（学生答卷主表） | FR-05-08 |
| `answers` | 答题记录表（每题作答） | FR-05-04 |
| `grade_tasks` | 阅卷任务表 | FR-06-03 |

### 4.3 关系说明

| 关系 | 基数 | 说明 |
|------|------|------|
| classes 1—N users | 一对多 | 一个班级多名学生 |
| users 1—N questions | 一对多 | 教师创建多道题目(creator_id) |
| users 1—N papers | 一对多 | 教师创建多份试卷(creator_id) |
| papers N—M questions | 多对多 | 通过 paper_questions 关联，含分值与排序 |
| users 1—N exams | 一对多 | 教师创建多场考试(creator_id) |
| papers 1—N exams | 一对多 | 一份试卷可被多场考试引用 |
| exams N—M classes | 多对多 | 通过 exam_classes 关联 |
| exams 1—N exam_records | 一对多 | 一场考试多名学生答卷 |
| users 1—N exam_records | 一对多 | 学生多条考试记录(student_id) |
| exam_records 1—N answers | 一对多 | 一份答卷含多题作答 |
| questions 1—N answers | 一对多 | 一道题目被多次作答 |
| exams 1—N grade_tasks | 一对多 | 一场考试多个阅卷任务 |
| users 1—N grade_tasks | 一对多 | 教师多个阅卷任务(teacher_id) |

### 4.4 索引策略

- **主键索引**：所有表自增 `id` 主键。
- **唯一索引**：`users.username`（登录唯一）、`classes.name`（班级名唯一）。
- **外键索引**：所有外键字段建立普通索引，加速关联查询。
- **查询索引**：
  - `questions`：(type, difficulty, knowledge_point) 联合索引，支撑题库筛选。
  - `exam_records`：(exam_id, student_id) 联合唯一索引，防重复答卷。
  - `answers`：(exam_record_id, question_id) 联合唯一索引，防重复作答。
  - `exam_records`：(exam_id, status) 索引，支撑阅卷任务查询。
- **软删除**：核心业务表（questions/papers/exams）使用 `deleted_at` 软删除，避免引用断裂。

## 5. 接口设计原则

### 5.1 RESTful 规范

- 资源化 URL：`/api/users`、`/api/questions`、`/api/papers` 等。
- HTTP 动词语义：GET 查询、POST 新增/动作、PUT 整体更新、PATCH 局部更新、DELETE 删除。
- 集合与单体：`/api/users`（集合）、`/api/users/:id`（单体）。
- 嵌套子资源：`/api/papers/:id/questions`（试卷下题目）、`/api/exams/:id/answers`（考试下答题）。
- 动作型接口使用 POST + 动词后缀：`/api/exams/:id/publish`、`/api/exams/:id/submit`、`/api/exams/:id/auto-grade`。
- 分页参数：`page`（页码，从 1 开始）、`pageSize`（每页条数，默认 10）。
- 筛选参数：以查询字符串传递，如 `?type=single&difficulty=3&keyword=函数`。

### 5.2 统一响应格式

所有接口统一返回如下 JSON 结构（满足 NFR-12）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { }
}
```

- `code`：业务状态码，200 表示成功，其他为错误码。
- `message`：中文提示信息。
- `data`：业务数据，失败时为 null 或省略。

分页响应 `data` 结构：

```json
{
  "list": [],
  "total": 100,
  "page": 1,
  "pageSize": 10
}
```

### 5.3 错误码体系

| 错误码 | HTTP 状态 | 含义 |
|--------|-----------|------|
| 200 | 200 | 成功 |
| 400 | 400 | 请求参数错误 |
| 401 | 401 | 未认证/令牌失效 |
| 403 | 403 | 无权限/越权访问 |
| 404 | 404 | 资源不存在 |
| 409 | 409 | 资源冲突（如重复创建、引用冲突） |
| 422 | 422 | 参数校验失败 |
| 500 | 500 | 服务器内部错误 |
| 1001 | 400 | 用户名或密码错误 |
| 1002 | 409 | 用户名已存在 |
| 1003 | 403 | 账号已禁用 |
| 2001 | 409 | 题目已被试卷引用，禁止删除 |
| 3001 | 409 | 试卷已被考试引用，禁止删除 |
| 4001 | 400 | 考试未在时间窗口内 |
| 4002 | 409 | 已交卷，不可重复提交 |
| 4003 | 403 | 考试进行中，不允许删除 |
| 5001 | 400 | 答案暂存失败 |
| 6001 | 404 | 阅卷任务不存在 |

## 6. 安全设计

### 6.1 认证机制（JWT）

**认证流程**：

1. 用户提交账号密码至 `POST /api/auth/login`。
2. 后端查询 `users` 表，bcrypt.compare 校验密码哈希。
3. 校验通过，签发 JWT（payload 含 `userId`、`role`、`iat`、`exp`），有效期 2h。
4. 前端将 JWT 存于 localStorage，Axios 请求拦截器注入 `Authorization: Bearer <token>`。
5. 后端认证中间件解析并校验 JWT，失败返回 401。
6. 令牌续期：前端在响应拦截器检测到即将过期时调用刷新接口或在请求头返回新令牌。

**JWT Payload**：

```json
{
  "userId": 1,
  "role": "teacher",
  "iat": 1761753600,
  "exp": 1761760800
}
```

### 6.2 RBAC 权限模型

| 角色 | 标识 | 可访问模块 |
|------|------|------------|
| 管理员 | admin | 用户管理、班级管理、系统配置、日志、全部只读 |
| 教师 | teacher | 题库管理、试卷管理、考试管理、阅卷、成绩统计(班级) |
| 学生 | student | 在线答题、个人成绩、答题详情、错题统计 |

**权限中间件实现**：路由声明所需角色，中间件从 JWT 解析 role 并校验，不匹配返回 403。示例：

```javascript
// 使用示例：router.post('/api/users', auth(), requireRole('admin'), userController.create);
```

### 6.3 密码加密

- 使用 bcrypt，saltRounds = 10。
- 注册/重置密码时 `bcrypt.hash(plain, 10)` 存储。
- 登录时 `bcrypt.compare(plain, hash)` 校验。
- 禁止任何日志/响应中输出密码明文或哈希。

### 6.4 SQL 注入防护

- 全部数据库操作通过 Sequelize ORM 参数化查询，禁止拼接 SQL（满足 NFR-07）。
- 原生查询（如统计）使用 `sequelize.query` 的 `replacements` 参数绑定。

### 6.5 XSS 防护

- 后端对用户输入（题干、选项、姓名等）进行 HTML 转义后存储。
- 前端 React 默认转义 JSX 插值；富文本（题目解析）使用白名单过滤（如 DOMPurify）。
- 设置响应头 `X-Content-Type-Options: nosniff`。

### 6.6 CORS 配置

- 开发环境允许 `http://localhost:5173`（Vite 默认端口）。
- 生产环境仅允许前端部署域名。
- 预检请求允许 `Authorization`、`Content-Type` 头。

### 6.7 其他防护

- **防暴力登录**：登录接口限流（express-rate-limit），5 次/分钟。
- **敏感数据最小暴露**：学生答卷、标准答案等接口严格鉴权，学生不可获取标准答案（阅卷完成前）。
- **HTTPS**：生产环境强制 HTTPS。

## 7. 核心业务流程

### 7.1 组卷流程

**文字描述**：
1. 教师进入试卷管理，选择"手动组卷"或"随机组卷"。
2. **手动组卷**：教师从题库列表按题型/知识点/难度筛选题目，勾选加入试卷，可调整题目顺序与分值。
3. **随机组卷**：教师设置组卷规则（题型分布、知识点、难度、各题型数量），系统从题库随机抽取满足条件的题目。
4. 系统创建 `papers` 记录，并写入 `paper_questions` 关联（含 score、sort_order）。
5. 教师设置试卷配置（总分、时长、及格线、是否乱序）。
6. 教师预览试卷确认无误，保存。

**流程图**：

```
开始 → 选择组卷方式
  ├─ 手动组卷 → 筛选题库 → 勾选题目 → 调整顺序/分值 → 保存关联
  └─ 随机组卷 → 设置规则 → 系统抽题 → 生成关联
→ 设置试卷配置 → 预览 → 保存 → 结束
```

### 7.2 考试流程（学生视角）

**文字描述**：
1. 学生登录，查看可参加的考试列表（状态为 published/ongoing 且在时间窗口内）。
2. 学生点击"进入考试"，后端校验：考试状态、时间窗口、学生是否在参考班级、是否已交卷。
3. 校验通过，创建/复用 `exam_records`（状态 ongoing），返回试卷题目（乱序处理）。
4. 学生答题，前端定时（如每 30s）或作答即时调用暂存接口，upsert 到 `answers` 表。
5. 前端倒计时显示，剩余 5 分钟弹窗提醒。
6. 防作弊：前端监听 visibilitychange/blur 记录切屏次数，超阈值警告或强制交卷；禁用复制/粘贴/右键。
7. 学生主动交卷 或 倒计时结束自动交卷：调用交卷接口，后端将 `exam_records.status` 置为 submitted，触发客观题自动阅卷。
8. 客观题自动阅卷完成，若无主观题则 `status` 置为 graded；有主观题则生成阅卷任务待教师处理。
9. 学生在阅卷完成后可查看答题详情与得分。

**流程图**：

```
登录 → 查看考试列表 → 进入考试(校验) 
→ [校验失败] → 返回提示 → 结束
→ [校验通过] → 加载试卷 → 答题循环 {
    作答 → 暂存答案 → 倒计时检查
    切屏检测 → [超阈值] → 强制交卷
  } 
→ 交卷(主动/自动) → 客观题自动阅卷 
→ [有主观题] → 生成阅卷任务 → 等待教师阅卷
→ [无主观题] → 直接完成
→ 阅卷完成 → 学生查看成绩 → 结束
```

### 7.3 阅卷流程

**文字描述**：
1. **客观题自动阅卷**（交卷时触发）：
   - 遍历 `answers` 中客观题（single/multiple/judge/fill）。
   - 比对学生答案与标准答案：单选/判断完全匹配；多选集合相等；填空去首尾空格后匹配（支持多空）。
   - 匹配则 `score = 题目分值, is_correct = true`，否则 `score = 0, is_correct = false`。
   - 记录 `graded_by = system, graded_at = now`。
2. **主观题手动阅卷**：
   - 教师查看阅卷任务列表（`grade_tasks`，按考试分组）。
   - 教师进入某学生答卷，逐题查看学生作答与参考答案，填写评分与评语。
   - 提交评分，更新 `answers.score, is_correct, graded_by, graded_at`。
3. **成绩汇总**：某学生所有题目评分完成，汇总 `exam_records.total_score`，状态置为 graded。
4. **成绩复核**：教师可对已阅卷答卷改分，保留修改记录（旧分/新分/修改人/时间）。
5. **阅卷进度**：统计某考试已阅卷/总答卷数，展示完成百分比。

**流程图**：

```
交卷 → 触发客观题自动阅卷 → 遍历客观题 → 比对答案 → 记算得分 → 更新 answers
→ [存在主观题] → 生成 grade_tasks → 教师查看任务列表 
  → 进入答卷 → 逐题评分 → 提交 → 汇总个人成绩
→ [无主观题] → 直接汇总
→ 全部阅卷完成 → 考试状态 finished → 成绩统计可查 → 结束
```

### 7.4 登录认证流程

```
用户输入账号密码 → POST /api/auth/login 
→ 查询 users(by username) → [不存在] → 返回 1001 用户名或密码错误
→ bcrypt.compare → [不匹配] → 返回 1001
→ [status=disabled] → 返回 1003 账号已禁用
→ 签发 JWT(userId, role, exp=2h) → 返回 { token, userInfo }
→ 前端存储 token → Axios 注入 Authorization → 后续请求携带 → 结束
```
