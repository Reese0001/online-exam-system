## 2. 背景和目标

### 2.1 背景

基于已完成的PRD文档，在线考试系统需要支持管理员、教师、学生三种角色的完整考试管理流程。系统需要实现题库管理、试卷组卷、在线考试、自动阅卷、成绩统计等功能。

### 2.2 设计目标

- **高可用性**：支持100人以下并发考试，系统可用性99.9%
- **可扩展性**：模块化设计，便于后续功能扩展
- **安全性**：用户认证、权限控制、数据加密
- **易用性**：响应式Web界面，支持PC和平板访问
- **高性能**：常规操作响应时间 < 2秒

## 5. 核心技术选型和理由

### 5.1 前端技术选型

| 技术 | 版本 | 选型理由 |
|-----|------|---------|
| React | 18+ | 组件化开发、生态成熟、虚拟DOM、适合SPA |
| TypeScript | 5.x | 类型安全、代码可维护性、减少运行时错误 |

| Vite | 5.x | 快速构建、HMR、开发体验优秀 |

### 5.2 后端技术选型

| 技术 | 版本 | 选型理由 |
|-----|------|---------|
| Node.js | 18+ | 前后端统一语言、高并发I/O、生态丰富 |
| Express.js | 4.x | 轻量级框架、中间件机制、学习成本低 |

### 5.3 架构模式

- **前后端分离**：前端SPA + 后端RESTful API

- **JWT认证**：无状态、分布式友好
- **响应式设计**：适配PC和平板设备

## 6. 数据流/调用链描述

### 6.1 用户登录流程

```
1. 用户输入账号密码
2. 前端发送POST /api/auth/login
3. 后端验证账号密码
4. 生成JWT Token
5. 返回Token给前端
6. 前端存储Token（localStorage）
7. 后续请求携带Token访问API
```

### 6.2 在线考试流程

```
1. 学生登录后获取考试列表
2. 选择考试，进入考试页面
3. 前端发送GET /api/exams/{id}/start
4. 后端验证考试状态，创建考试记录
5. 返回试卷信息和考试配置
6. 前端加载试题，开始答题
7. 每30秒自动保存答题进度
8. 答题完成，发送POST /api/answers/submit
9. 后端自动评分（客观题）
10. 返回成绩和答题详情
```

### 6.3 阅卷流程

```
1. 教师获取待阅卷列表
2. 选择学生试卷
3. 查看主观题答案
4. 输入分数和评语
5. 发送POST /api/reviews/{id}
6. 后端保存分数
7. 所有主观题阅卷完成后，计算总分
8. 更新最终成绩
```

## 8. 非功能设计

### 8.1 可用性设计

- **自动保存**：考试答题每30秒自动保存，防止数据丢失
- **断网续答**：本地缓存答题数据，网络恢复后同步
- **错误处理**：统一的错误处理机制，友好的错误提示
- **日志记录**：完整的系统日志，便于问题排查

### 8.2 扩展性设计

- **模块化**：各模块独立开发、测试、部署
- **插件化**：支持后续扩展新题型、新功能
- **配置化**：系统参数可配置，便于调整

### 8.3 安全性设计

- **认证**：JWT Token认证，Token有效期2小时
- **权限控制**：基于角色的访问控制（RBAC）
- **密码加密**：bcrypt加密，盐值加密
- **输入验证**：前后端双重验证，防止XSS攻击
- **SQL注入**：使用参数化查询，防止SQL注入
- **HTTPS**：生产环境使用HTTPS加密传输

### 8.4 性能设计

- **数据库优化**：合理设计索引，优化查询语句
- **缓存策略**：Redis缓存热点数据（可选）
- **分页查询**：列表接口支持分页，避免大数据量查询
- **静态资源**：Nginx托管静态资源，CDN加速

## 10. 风险和开放决策

### 10.1 风险评估

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|------|------|---------|
| 考试期间系统崩溃 | 高 | 中 | 自动保存、定期备份、快速恢复 |
| 网络中断 | 高 | 中 | 本地缓存、断网续答 |
| 并发量过大 | 中 | 低 | 负载均衡、缓存优化 |
| 数据丢失 | 高 | 低 | 定期备份、事务保护 |

### 10.2 开放决策

1. **前端路由模式**：选择Hash模式（兼容性好）vs History模式
   - **决策**：选择Hash模式，部署简单，无需服务器配置

2. **状态管理方案**：Redux vs Zustand vs Context API
   - **决策**：选择Redux Toolkit，生态成熟，中间件支持完善

3. **文件存储方式**：本地存储 vs 云存储
   - **决策**：V1.0使用本地存储，V2.0考虑云存储

4. **实时通知**：WebSocket vs 轮询
   - **决策**：V1.0使用轮询，V2.0考虑WebSocket
